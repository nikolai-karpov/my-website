# Что делать с коллизиями ОКОГУ

Ответ — не матрица и не пачка таблиц. Ответ — правило: запись и строка crosswalk попадают ровно в один из трёх классов, у класса одна реакция.

Десяток известных случаев это правило проверяет. Он его не задаёт.

Полнота — не «120 ячеек просмотрены» и не «запрос вернул 0 строк». Полнота: сумма классов равна числу записей, остаток назван, вычеркнутое вычеркнуто инвариантом.

## Снято с предыдущей карты

- Матрица 5×4×2×3 как список всех случаев. Это рисковое подмножество осей. Универсумом она не становится.
- «0 строк в текущей БД — комбинация недостижима». Не наблюдалось не значит невозможно. Случаи этой задачи в текущем срезе как раз отсутствуют.
- Таблица вариантов на каждую дырку. Она возвращает десяток частных решений, который надо сжать.
- `successor_code` в единственном числе. Разделение ведомства — это `new_codes[]`.
- Crosswalk как поздний документ одного перехода v11→v12. Он вход классификации и переживает следующую версию.
- Прецеденты MDM/LEI как колонка выбора. Эталона в задаче нет.

Матрица остаётся внизу, как атака на уже написанную функцию. По умолчанию её не строят.

## Инвариант

Запись остаётся интерпретируемой на ноде, которая применила версию справочника V, на valid time записи. Новый приём кода без интерпретации запрещён. История не удаляется и не переписывается наугад.

Два подписанных инварианта («историю переписываем» и «историю только читаем») — стоп. Это не дырка матрицы, а неснятое противоречие требования.

## Предикат

```
collision(
  record,
  source_directory_version,
  receiver_directory_version,
  crosswalk_row,
  operation            -- read | accept | migrate | replay
) → R | A | S
```

Два времени. Bitemporal-хранилище не заводим.

- `valid_time` — на какую дату запись претендует быть истинной.
- `directory_knowledge_time` — когда эта нода узнала о событии справочника.

Хранилище с двумя осями времени нужно только если теневой прогон покажет: одна и та же запись требует двух реакций в зависимости от времени знания. До этой находки хватает двух полей в предикате.

Своя запись и чужая — не классы. «Уже лежит», «ещё принимается», «миграция», «повторная доставка» — параметр `operation` внутри реакции. Отдельным классом ось становится только если тест членства ниже провален.

## Контекст LLM

В вызов попадает только инвариант, функция членства, подписанная версия crosswalk и один объект. Прошлые ответы модели, кандидаты со статусом `candidate` и чужие карточки не подавать.

Где ниже написано «LLM не вызывается» — ограничения нет, потому что нет вызова.

## Шаг 0. Зафиксировать инвариант

**Вход:** формулировка задачи. Ведомство аннулировано или разделено на два. Невалидны уже лежащие записи ноды и записи, которые нода принимает от другой.

**Выход:** одно предложение инварианта и сигнатура предиката. Подпись.

**Кто:** человек. LLM не вызывается.

**Применимость:** всегда, до дифа и до карточек.

**Где ломается:** в документе два инварианта, или инвариант не различает новый приём и уже лежащую запись. Предикат тогда не из чего собрать.

---

## Шаг 1. Crosswalk из дифа

Причина коллизии — изменение справочника, не тикет. Класс записи считается по строке crosswalk. Строки нет — членство только в остатке.

**Вход:** диф справочника между версиями.

**Выход:**

```
crosswalk_version, source_version, target_version,
old_code, new_codes[], type,     -- split | merged | renamed | annulled | resubordinated
effective_from, effective_to,
status,                          -- candidate | verified | superseded
rationale, verified_by, verified_at
```

`new_codes` — массив. У аннулирования он пустой. У разделения длина больше 1. Тип `split` и один код — брак строки, не запись.

**Кто:**

- Скрипт разбирает диф, если тип изменения в нём явный. LLM для этого не нужен.
- Человек верифицирует сначала аннулирования и все строки, где `|new_codes| ≠ 1`.
- LLM предлагает кандидатов только на строках, которые диф сам не типизирует. Статус — `candidate`. Пакетом в `verified` не поднимать. Преемника по похожести имени модель может показать и не может утвердить.

**Применимость:** диф есть. Нет дифа — шаг блокирует. Строки из тикетов не выдумывать.

**Где ломается:** `verified_at` в тот же день, что генерация, на строках split; артефакт назван «v11→v12» и не имеет `crosswalk_version`.

## Шаг 2. Карточки и теневой прогон

Известный десяток и старые данные дают один выход: статус строки crosswalk на записи. Второе не ждать миграции.

### 2a. Десяток, который уже всплыл

**Вход:** лог, тикет, стенд, память — как есть.

**Выход:**

```
case_id, operation, entity_type, entity_id,
okogu_code, record_status,
valid_time, directory_knowledge_time,
source_node, receiver_node,
source_directory_version, receiver_directory_version,
crosswalk_version, crosswalk_status,   -- unique | empty | multi | missing | unverified
successor_cardinality,
source_refs, missing_fields
```

Свободный текст симптома полем решения не хранить. Источник остаётся в `source_refs`.

**Кто:** LLM извлекает поля из сырья. Запрет: достраивать пропуск правдоподобным значением. Нет данных — `unknown`, имя поля в `missing_fields`. Проверка формы — JSON Schema. Человек подтверждает, что карточка про этот случай, а не про соседний.

**Ворот:** на полях предиката стоит `unknown` — карточку в функцию членства не класть. Сначала добрать поле.

### 2b. То, что ещё не всплыло

**Вход:** исторические записи и черновик crosswalk. Отдельный вход — выборка сообщений, принятых от другой ноды.

**Выход:** у записи `crosswalk_status` и черновой класс. Счётчики. Выборка статусов `multi`, `missing`, `unverified`.

**Кто:** join. LLM таблицу не классифицирует.

**Применимость:** есть чтение старых записей. Нет доступа — 2a и черновик функции делаются всё равно, выбор реакции блокируется до счётчиков.

**Где ломается:** прогон читает операционную таблицу, а старые коды лежат во входящем архиве. Для чужих записей нужен стенд: приёмник на новой версии, выборка источника на старой. Проба, где обе стороны уже на новой версии, рассинхрон не показывает.

---

## Шаг 3. Три класса

Класс — реакция, которую нода обязана совершить. Тип события справочника класс не называется. Кластеризовать карточки нельзя: аннулирование склеится само с собой, хотя чтение истории и новый приём разные, а переименование оторвётся от слияния, хотя реакция одна.

**Функция.** Сверху вниз, запись получает ровно один класс:

1. Строка `verified` и `|new_codes| = 1` → **R**. Сюда же код, который в целевой версии ещё действует: интерпретация и так одна.
2. Иначе строка `verified`, тип `annulled`, `new_codes` пуст → **A**.
3. Иначе → **S**. Разделение, нет строки, статус `candidate`, преемников несколько, кардинальность неизвестна.

Строка, которая спорит сама с собой (аннулирование с непустым `new_codes`, разделение с одним кодом), в функцию не входит. Её чинят на шаге 1.

| Класс | Членство | Что из этого следует для реакции |
|---|---|---|
| R | интерпретация одна, строка проверена | код можно подставить без человека |
| A | ведомства нет, преемника нет, строка проверена | преемника нельзя выдумать; новый приём нельзя; историю нельзя стереть |
| S | всё остальное | преемника нельзя выбрать по имени; пакетом это не решается |

**Три проверки.**

- Ровно один класс. Ноль или два на одну запись — противоречивая строка crosswalk либо дыра в приоритете. Новым случаем это не называется.
- Одна реакция внутри класса. Две карточки одного класса требуют разных реакций — класс невалиден. Ось возвращается параметром. Не помогло — классов становится четыре. Четыре как исход теста допустимы. Четыре как имена событий справочника — нет.
- Покрытие шире десятка. Функция гоняется по строкам crosswalk и по теневому прогону. R + A + S = N. S определён как «не R и не A», поэтому ещё не виденный случай падает в него без новой матрицы.

Типичный провал второй проверки: входящий код класса R хочется отклонять, пока источник не сменил версию. Рассинхрон версий тогда пишется параметром реакции R. Если при том же параметре реакции всё равно две — это уже четвёртый класс, и его заводят здесь, не в матрице.

**Пример.**

- 123 переименован в 456, строка проверена, преемник один, запись своя. R. Миграция пишет 456, старый код остаётся в provenance. Чтение до миграции резолвит. Входящее с 123 — тоже R, `operation = accept`: подставить на приёме.
- 789 аннулирован, преемников нет, запись уже принята от другой ноды. A. Tombstone, новые операции с 789 отклоняются, история читается. Чужое происхождение класс не меняет.
- 555 разделён на 5551 и 5552, дискриминатора у записи нет. S. В карантин эта запись. Миграцию целиком не останавливать. 5551 по похожести имени не брать.

**Кто:** функцию пишет человек. Проецирует скрипт. LLM классы не именует. Единственный допустимый вызов — пометить карточку, чей текст источника спорит с присвоенным классом. В контекст — канон и эта карточка.

**Где ломается:** классы называются Annulled / Split / Renamed.

## Шаг 4. Одна реакция на класс

**Вход:** R, A, S и счётчики шага 2b. Пока счётчиков нет, реакции можно набросать, нельзя утверждать, что миграцию надо останавливать.

Меню человек пишет один раз:

| Механизм | Куда |
|---|---|
| Подставить единственный код, старый оставить в provenance | только R |
| Tombstone, история читается, новый приём отклонён | только A |
| Карантин записи, остальные коды мигрируют | только S |
| Окно, в котором старый код ещё принимается | не класс. Параметр R, если у строки заданы `effective_from` и `effective_to` |
| Остановка всей миграции | не реакция по умолчанию. Вместо карантина S, только с явным порогом доли S |

События — часть реакции, не отдельная платформа. Здесь фиксируются имя и поля. Код пишется после выбора.

- A: `AuthorityAnnulled { code, effective_from, crosswalk_version }`. Приёмник применяет идемпотентно. Локальный tombstone без события не мешает другой ноде слать старый код.
- S: `AuthoritySplit { old_code, new_codes, effective_from, resolution }`. Пока человек не назначил преемника конкретной записи, `resolution = unresolved`. Назначение преемника записи не превращает split в строку с одним кодом: на уровне кода единственного преемника нет.

**Кто выбирает:** человек.

**LLM:** один проход на класс — противоречит ли реакция инварианту. Стоимость числами не заполнять. Если после счётчиков на одном классе живы два механизма, в ячейке `MEASURE_ON_STAND` и один эксперимент. Шесть механизмов на пятнадцать дыр не замерять.

**Выход:** три строки. Класс, реакция, параметр `operation`, событие, что необратимо. В схеме реакции есть `new_codes[]`.

**Где ломается:** реакций больше, чем классов, и инвариант их не различает.

## Шаг 5. Полнота

**Вход:** функция, верифицированный crosswalk, счётчики теневого прогона, результат пробы входящих.

**Выход:**

- R + A + S = N по историческим записям и отдельно по выборке входящих. Не сошлось — прогон смотрит не в ту таблицу.
- Остаток S с владельцем. Ноль в S не требуется. Неразобранный S — это случаи, пойманные до миграции.
- Комбинации, которые вычеркнуты. Причина — инвариант или брак строки crosswalk. Пустой SELECT причиной не является.
- Исходный десяток: карточка без `unknown` на полях предиката лежит ровно в одном классе.

**Кто:** суммы считает скрипт. Список исключений LLM может набросать из инварианта и не может сократить. Подписывает человек.

**Запрет:** снимать комбинацию, потому что текущая БД вернула 0 строк. Ноль строк значит «в этом срезе не было».

**Где ломается:** в отчёте только десять карточек и нет равенства по историческим записям.

---

## Шаг 6. Следующий случай до миграции

**Вход:** коды активной версии, коды верифицированного crosswalk, коды записей, коды входящих.

**Выход:** разность множеств. Код есть в данных и нет ни в версии, ни в crosswalk — карточка шага 2a, статус `missing`, класс S. Запрос по расписанию.

**Кто:** запрос. LLM не нужен. Детектор аномалий сверх разности не строить, пока не стоит этот запрос: он не увидит случая, которого нет в разности.

**Где ломается:** сравнение только с активной версией, без crosswalk. Каждый исторический код становится сигналом, и на сигнал перестают смотреть.

---

## Матрица — только атака на функцию

По умолчанию не строить. Запускать, если тест «одна реакция внутри класса» красный или человек отказывается лечить конкретную запись реакцией S.

Оси задаёт человек. Если атака понадобилась, хватает трёх:

| Ось | Зачем |
|---|---|
| статус crosswalk | ключ функции; ячейка без смены реакции случаем не является |
| operation | параметр не должен прятать вторую реакцию |
| версия источника против версии приёмника | единственная распределённая развилка, которой нет в ключе |

До шага 4 цитировать нечего: политики ещё нет. Пометка модели `NOT_DEFINED` на ячейке тогда ни о чём не говорит. После шага 4 покрытие ячейки проверяет скрипт по таблице из трёх реакций.

## Порядок

**Неделя 1.** Хватает дифа и известного десятка.

1. Шаг 0.
2. Шаг 1. Сначала аннулирования и разделения.
3. Шаг 2a. Ворот по `missing_fields`.
4. Черновик функции и проекция десятка.

К концу недели правило есть. Знаменателя ещё нет, остановку миграции выбирать рано.

**Неделя 2.** Нужны старые записи и выборка входящих.

1. Шаг 2b и стенд с разными версиями источника и приёмника.
2. Шаг 4 на счётчиках. Доля S решает, нужен ли порог остановки.
3. Шаг 5.
4. Шаг 6 один раз вручную, затем то же самое по расписанию.

**Не делать, пока нет сигнала из проверок шага 3 или из остатка S.**

- Прогон матрицы.
- Замеры всех механизмов.
- Код событий. Имена фиксируются на шаге 4.
- Bitemporal-хранилище.
- Синтетические случаи вместо теневого прогона.

## Карта снова не про тот вопрос, если

- Контрпример снят, потому что запрос вернул 0 строк.
- Классы названы типами событий справочника.
- У разделения в crosswalk один код, а `verified_by` стоит с дня генерации.
- Реакций больше трёх, инвариант их не различает.
- `source_directory_version` у карточек пустой, стенд зелёный только когда обе ноды уже на новой версии.
- В готовности числятся матрица и нет R + A + S = N.

## Готово

1. Инвариант подписан.
2. У crosswalk есть версия. Аннулирования и разделения проверены человеком.
3. Функция R/A/S спроецирована на десяток без двойного членства.
4. Реакций три. В схеме есть `new_codes[]`. У A и S есть имя события.
5. R + A + S = N по истории и по выборке входящих. Остаток S назван.
6. Set-diff учитывает crosswalk.

Матрица, синтетика и прецеденты в готовность не входят.

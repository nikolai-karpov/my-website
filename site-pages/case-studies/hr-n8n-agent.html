Проблема

Записи встреч не превращаются сами в управленческие артефакты

У HR и руководителей накапливаются аудиозаписи собеседований и оценочных бесед. Ручная расшифровка долгая, а дальше каждый тип встречи исторически оформлялся разными шаблонами. Нужна была одна дисциплина: загрузил файл — получил согласованную структуру вывода без переключения между инструментами.

Решение

Оркестрация в n8n с явной маршрутизацией

Точка входа — Telegram: пользователь отправляет голосовое или файл. Цепочка получает бинарные данные, отправляет их в сервис транскрибации с поддержкой спикеров и русского языка, затем сопоставляет голосовые сегменты с известными участниками через отдельный HTTP-сервис и передаёт сырой текст в LLM для оформления полной стенограммы с ролями и условными таймкодами.

После сохранения результата бот предлагает меню: получить транскрипт, запустить авто-классификацию типа HR-встречи или выбрать анализ вручную. Классификатор относит запись к одному из шести типов (от интервью с кандидатом до комплексной оценки сотрудника); для каждого типа вызывается свой строго структурированный промпт крупной модели. Ответ нормализуется под HTML для Telegram, при необходимости режется на части по лимитам мессенджера; параллельно предусмотрена конвертация Markdown в DOCX и отправка на e-mail через SMTP.

Укрупнённый поток:

1
Триггер и файл
Telegram-бот принимает аудио или документ, извлекает идентификаторы чата и файла
2
Транскрибация и спикеры
Внешний API распознаёт речь; кастомный матчер обогащает подписи спикеров
3
Стенограмма
LLM приводит текст к протоколу: роли, уверенность, полнота без сокращений смысла
4
Тип → анализ
Switch по действию пользователя или по классу встречи; отдельная ветка для «неизвестного» типа с логированием
5
Доставка
Inline-меню: сообщения в Telegram, письмо, вложение Word; обработка ошибок и повторных запросов

Инженерный фокус

Не только промпты, но и устойчивость пайплайна

В проекте заложены разделение «сообщение vs callback» для корректной работы inline-кнопок, хранение состояния сессии (ожидание e-mail, привязка к ключу сообщения), очистка устаревших записей, ветки retry при временных сбоях LLM и отдельные обработчики ошибок транскрибации и классификации. Это снижает «залипание» сценариев в продакшене и упрощает сопровождение.

Эффект

Единый HR-контур на no-code оркестраторе

Специалист по персоналу остаётся в привычном Telegram, а тяжёлая цепочка — распознавание, обогащение, выбор методики анализа и форматы выдачи — инкапсулирована в воспроизводимом workflow. Такой подход хорошо масштабируется сменой промптов и подключением корпоративных политик хранения данных без переписывания «с нуля».

Orchestrate subagents at scale:
Claude Code Dynamic Workflows

JavaScript-скрипт, который координирует множество субагентов для масштабных задач: аудиты всей кодовой базы, миграции сотен файлов, перекрёстная проверка исследований. Сессия остаётся отзывчивой, агенты работают в фоне, прогресс виден в реальном времени.

Что это за фича и когда появилась

Dynamic Workflows — новая фича Claude Code (версия 2.1.154+), добавлена в Week 22 (25–29 мая 2026). Доступна на всех платных тарифах (Pro, Max, Team, Enterprise), требует Anthropic API или интеграции с AWS Bedrock / Google Vertex / Microsoft Foundry. В CLI включается через настройку Dynamic workflows в /config.

Research preview — фича созревает, но уже используется для реальных задач. Ключевое отличие от обычных субагентов: план живёт в коде, а не в голове Claude, и может быть перезапущен, прочитан и переиспользован.

Ключевые отличия workflow

План в коде, а не в голове Claude

С субагентами, скиллами и командами — Claude каждый раз заново решает, что делать дальше, что запускать, что собирать в итог. Workflow-скрипт хранит цикл, разветвления, промежуточные результаты. Контекст сессии получает только финальный ответ.

Повторяемые паттерны качества

Workflow не просто масштабирует — он может применить повторяемый паттерн качества: независимые агенты конфликтно проверяют результаты друг друга перед тем, как сообщить; план прорабатывается с нескольких углов, варианты взвешиваются между собой.

Когда использовать workflow

Используйте workflow, когда:

  • Задача больше, чем может координировать одна сессия: кодовый аудит всего репозитория, миграция 500 файлов, исследование с перекрёстной проверкой источников
  • Нужен план, который можно перезапустить и читать как код
  • Нужно, чтобы результаты были верифицированы против друг друга

Не используйте для:

  • Очевидных задач в один ход (исправить опечатку, добавить лог-строку)
  • Задач, где можно описать diff в одно предложение
Пример запроса:
ultracode: audit every API endpoint under src/routes/ for missing auth checks

Как запустить workflow

Встроенный workflow: /deep-research

Самый быстрый способ попробовать — запустить /deep-research с вопросом:

/deep-research What changed in the Node.js permission model between v20 and v22?

Claude запускает агентов в фоне, вы видите прогресс в панели задач или через /workflows. В конце — отчёт с цитатами, фильтрацией неподтверждённых утверждений.

Попросить Claude написать workflow

Два способа:

  • Ключевое слово ultracode в промпте
  • Естественный запрос: «use a workflow» или «run a workflow»

Claude пишет скрипт для задачи, запускает в фоне. Если вы не хотели запускать workflow — Option+W на macOS или Alt+W на Windows отклоняет для этого промпта.

Ultracode режим

/effort ultracode — включает высокий уровень рассуждения и автоматическую оркестрацию workflow для каждой существенной задачи. Одна задача может превратиться в несколько workflow подряд: понять код, сделать изменения, проверить. Применяется к каждой задаче сессии — больше токенов, больше времени. Сбрасывается при новой сессии. Доступно только на моделях, поддерживающих xhigh.

Сохранение workflow

Запустите /workflows, выберите прогон, нажмите s. Выберите место:

  • .claude/workflows/ — проектный, общий для всех кто клонирует репо
  • ~/.claude/workflows/ — личный, виден всем проектам, только вам

В будущем вызывается как /имя.

Стоимость

Workflow запускает много агентов — один прогон может использовать значительно больше токенов, чем проработка той же задачи в диалоге. Считается к лимитам вашего тарифа и rate limits как и любая сессия.

Чтобы оценить расход до большой задачи — прогоните на тестовом срезе: одна папка вместо всего репозитория, узкий вопрос вместо широкого. /workflows показывает расход токенов каждого агента по мере прогона.

Каждый агент в workflow использует модель сессии, если скрипт явно не маршрутизирует этап на другую. Чтобы контролировать стоимость модели:

  • Проверьте /model перед большим прогоном
  • Попросите Claude использовать более дешёвую модель для этапов, которые не требуют самой мощной

Практические советы

Для малых задач

  • Используйте обычные субагенты — дешевле и быстрее
  • Проверьте /.claude/workflows/ — возможно, уже есть готовый workflow

Для больших задач

  • Включите /effort ultracode для сложных задач
  • Запустите на тестовом срезе до полного прогона
  • Следите за расходом через /workflows
  • Сохраните удачный workflow для повторного использования

Для команд

  • Сохраняйте полезные workflow в .claude/workflows/ — общий репозиторий
  • Настройте permission mode для минимизации прерываний
  • Добавляйте команды в allowlist для долгих прогонов

Резюме для практики

Dynamic Workflows — не панацея. Используйте, когда:

  • Задача явно больше «починить баг» или «добавить функцию»
  • Нужно несколько проходов и верификация
  • Масштаб оправдывает стоимость

Начните с /deep-research, сохраните полезные workflow, накапливайте опыт. Для большинства задач хватит субагентов и скиллов.

# Комплект резюме и портфолио

Сайт поддерживает один ZIP с двумя PDF. Сборщик копирует PDF без изменения содержания, сравнивает SHA-256 и пересобирает весь архив при изменении любого из двух документов. Изменение только времени файла не вызывает пересборку.

## Источники

По умолчанию используется локальная папка Яндекс Диска:

```text
~/Yandex.Disk.localized/Трудоустройство/Резюме/IT/
```

- `Руководитель_направления_AI-решений.pdf`: резюме.
- `Портфолио/dist/Николай_Карпов_AI_портфолио.pdf`: готовое портфолио.

Сначала завершить экспорт обоих PDF и синхронизацию Яндекс Диска. Изменение исходников портфолио в `src/` не означает обновление PDF: его нужно собрать в проекте портфолио отдельно. Каталоги рекомендаций, архивы, DOC, HTML и прочие соседние материалы в комплект не входят и сборщиком не читаются.

Для другой локальной папки с той же структурой:

```bash
CAREER_BUNDLE_SOURCE_DIR="/путь/к/IT" npm run bundle:sync
```

Либо `npm run bundle:sync -- --source-dir "/путь/к/IT"`. Не сохранять персональные абсолютные пути в публикуемые страницы или манифест.

## Обновление

1. Обновить предназначенные для публикации исходные PDF. Владелец 06.11.2026 подтвердил, что актуальное резюме содержит только публикуемую информацию; разрешение на комплект отражено в `docs/career-profile.md`.
2. В текущем проекте выполнить `npm run bundle:sync`.
3. Выполнить `npm run bundle:check` и `npm run bundle:verify`.
4. Проверить скачивание локально, имена и содержание обоих PDF в архиве.
5. Только по отдельному поручению опубликовать согласованные изменения: ZIP, JSON-манифест и обе страницы со ссылками. Подготовка файлов сама по себе не является коммитом или деплоем.

```bash
npm run bundle:sync
npm run bundle:check
npm run bundle:verify
npm run test:bundle
npm run check:bundle-ui
```

Если исходники не изменились и результаты целы, ZIP, манифест и страницы не перезаписываются. При изменении SHA-256 хотя бы одного PDF обновляется весь ZIP, контрольные суммы, размер и версия ссылок. Параметр версии в URL предотвращает повторное использование старого архива из кэша.

В архив входят только `Nikolai_Karpov_Resume.pdf` и `Nikolai_Karpov_Portfolio.pdf`. Они побайтно совпадают с исходниками. Даты и права ZIP-записей нормализованы, чтобы одинаковые входы давали воспроизводимый архив.

Не редактировать ZIP, JSON и содержимое HTML между `career-bundle:start/end` вручную: их согласованность проверяется сборщиком. Оформление находится в исходном `assets/css/style.css`; это не legacy-файл `main.css`.

## Проверки и остановки

- `bundle:sync`: проверяет наличие и целостность исходников, затем при необходимости собирает комплект. Требует Python 3.10+; используются только модули стандартной библиотеки.
- `bundle:check`: проверяет актуальность относительно обоих исходников без записи. Отсутствие исходников, повреждённый или устаревший комплект означают ненулевой код выхода.
- `bundle:verify`: проверяет подготовленный ZIP, точный список файлов, CRC, размеры, SHA-256 и ссылки, не обращаясь к Яндекс Диску. Используется CI перед загрузкой артефакта сайта.
- Если первый публичный комплект ещё не подготовлен, `bundle:verify` допускает отсутствие и ZIP, и манифеста только при корректной ссылке «Запросить комплект». Это безопасное резервное состояние, а не подтверждение готовности скачивания.

Сборщик не является редактором или автоматическим цензором: он не удаляет сведения из PDF и не пересматривает подтверждённое владельцем разрешение на актуальные документы по устаревшим спискам. При обновлении в эти два файла должны попадать материалы, предназначенные для публичного скачивания. Разрешение не распространяется на соседние документы, рекомендательные письма и новые статьи.

Если исходники не прочитаны или неполны, прежние результаты не заменяются. Это **блокирует выпуск нового комплекта**, даже если старый архив всё ещё существует. Завершить экспорт и синхронизацию, затем повторить команду. При повреждении архива, манифеста или ссылок `bundle:sync` восстанавливает их из прошедших проверки источников.

## Первый выпуск

06.11.2026 владелец подтвердил допустимость публикации актуального резюме. Публичный комплект собирается из двух указанных PDF без правок, обезличивания или добавления соседних файлов. Подготовка комплекта локально не означает, что он уже опубликован на действующем сайте.

## Где запускается правило

Обязательная инструкция находится в корневом `AGENTS.md`. Она предписывает проверку перед подготовкой публикации и после изменения PDF. Это не фоновый наблюдатель: изменения на Яндекс Диске не запускают процесс сами по себе. Не устанавливать системный планировщик или watcher без отдельного поручения.

GitHub Actions не имеет доступа к локальному Яндекс Диску: он только проверяет согласованность уже подготовленных файлов. Legacy-команда `npm run build` не является сборкой этого комплекта и не используется вместо `bundle:sync`. Онлайн-версия меняется только после явной публикации подготовленных артефактов.

## Регрессия

`test:bundle` создаёт только синтетические PDF во временных подпапках игнорируемого `build/`, проверяет пересборку при изменении каждого файла, неизменность при повторном запуске и смене mtime, побайтное содержимое, ошибки исходников, повреждение ZIP и ссылок. Настоящие PDF тесты не меняют и не подменяют.

`check:bundle-ui` использует установленный Playwright и локальный сервер на свободном порту. Проверяет обе страницы, светлую и тёмную темы, ширины 320/375/768/1440/2560/5120 CSS px, фокус, скачивание клавиатурой с проверкой SHA-256, работу без JavaScript и увеличение текста блока. Внешние запросы блокируются, формы не отправляются. Скриншоты остаются в `build/career-bundle-checks/`, сервер и браузер закрываются после проверки. Если Chromium не установлен, сначала установить его средствами существующего Playwright-окружения.

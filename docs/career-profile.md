# Career Profile Source of Truth

Этот файл нужен для будущих Codex-сессий: он собирает рабочее позиционирование Николая Карпова, проверенные опорные кейсы и идеи для развития портфолио. Перед публичными правками сайта или ответами HR нужно сверять факты с исходными файлами.

## Как использовать

1. Для HR-ответов и карьерных задач сначала читать этот файл, затем:
   - `docs/resume.md`
   - `docs/for-website-cases.md`
   - `index.html`
   - `site-pages/`
   - `cases/warehouse_logistic/`
2. Не придумывать опыт, метрики, стеки и внедрения. Если факт есть только со слов пользователя в текущей сессии, явно помечать его как требующий подтверждения.
3. Для hh/HR-ботов писать коротко, по-русски, без пафоса и без англицизмов, если они не нужны для точного названия технологии.

Остаётся уточнить перед HR-ответами или расширением публичного кейса:

- были ли заказчики, пилотные показы, договорённости или ограничения NDA, которые можно публично раскрывать;
- есть ли отдельные документы, подтверждающие промышленную эксплуатацию или сертификационный статус платформы.

Сильная подача: промышленный демонстратор / data provenance / immutable audit trail для телеметрии поставок — прослеживаемость, доверенный журнал событий, контроль нарушений и расчёты на базе смарт-контрактов.

## Как усилить портфолио

### Добавить / усилить в первую очередь

1. **Складская логистика в промышленном холдинге**
   Уже есть страница `site-pages/carriers-platform.html`. Кейс нужно держать во второстепенном блоке сайта, потому что он не был выведен в production по решению заказчика: подтверждённый результат — архитектура, техническое задание, карта интеграций и макеты/HTML-прототип. Усиливать можно формулировкой про быстрый прототип, если пользователь подтвердит публичность срока "за неделю".

2. **Блокчейн и нефтегазовая телеметрия**
   Добавлена страница `site-pages/blockchain-lab.html`. Держать честную рамку: пилотный демонстратор / физический макет / интерфейс, без заявлений о production-внедрении. Сильный отраслевой сигнал: промышленный data governance, прослеживаемость, неизменяемый аудит, IoT-телеметрия, ГОСТ-криптография и смарт-контракты.

3. **ERP/WMS/1C/BI как отдельный карьерный блок**
   Сейчас этот опыт есть в резюме, но для сайта его можно вынести в отдельную страницу или секцию "Enterprise systems and integration": 1С, ERP, WMS, Power BI, REST/XML, единый источник истины, управленческая отчётность.

4. **AI-аудит промышленного холдинга**
   Усилить не количеством идей, а качеством методологии: интервью, AS-IS/TO-BE, паспорт данных, классификация пилотов по ИБ, short-list/long-list, финансовая рамка, дорожная карта.

5. **Безопасный LLM-контур и псевдонимизация**
   Это дифференциатор для банков, промышленности, ритейла и логистики: пользователь умеет не только "прикрутить GPT", а пройти путь через ИБ и защищённые данные.

6. **Персональный мультиагентный AI-оркестратор**
   Подавать как production-практику инженерного мышления: fallback моделей, логирование, память, анализ ошибок, автоматизация рутины. Не выдавать за enterprise-внедрение у клиента, если речь о собственной системе.

### Что добавлять осторожно

- "Смарт-контракты" и "блокчейн" — только с чётким описанием бизнес-задачи, иначе звучит как buzzword.
- Метрики экономического эффекта — только если есть источник или пользователь подтверждает, что цифру можно раскрывать.
- Названия заказчиков и внутренние названия систем — анонимизировать, если нет разрешения.

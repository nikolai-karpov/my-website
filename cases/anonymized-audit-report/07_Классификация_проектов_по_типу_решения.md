# 07. Классификация проектов по типу решения

> Проекты разделены на три класса в соответствии с **докладной запиской (разделы 3.1.1, 3.1.2, 3.2)**. Деление основано не на бизнес-приоритете, а на **типе технического решения и совместимости с политикой ИБ**.

| Класс | Что входит | Зависимость от инфраструктуры |
|------------------------------------|-----------------------------------------------------------------------|---------------------------------------------------------------|
| **3.1.1. Проекты ИИ — внешние API** | Использование ChatGPT / Claude / DeepSeek / GigaChat / Я.GPT через прямой API | Сервер не требуется; политика ИБ требует, чтобы данные не были КТ |
| **3.1.2. Проекты ИИ — локальный сервер** | Те же сценарии, но с защищённой On-premise LLM | Сервер обязателен (ожидается + ввод в эксплуатацию) |

## 7.5. Принципы запуска (общие для всех классов)

### 7.5.1. У каждого проекта — Product Owner от бизнеса
Без выделенного Product Owner с мандатом 4–6 ч/мес проект не запускается.

### 7.5.2. У каждого проекта — критерии stop/go
| Решение | Условие |
|-------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| 🚀 Масштабирование | Критерий успеха достигнут, Product Owner подтверждает ценность, бюджет выделен |
| 🔄 Доработка | Критерий не достигнут, но есть инсайты — ТЗ корректируется, второй цикл |
| ⛔ Закрытие | Критерий не достигнут, экономика не сходится — закрываем |

### 7.5.3. Двойной бюджет (для 3.1.2)
Смета пилота + смета масштабирования формируется **до старта пилота** и актуализируется по итогам.

### 7.5.4. Человек в контуре валидации
В пилотах ИИ **не принимает решения автоматически** — только рекомендации.

## 7.6. Что НЕ запускается без доделки аудита

⚠️ Некоторые проекты класса 3.1.2 заблокированы белыми пятнами и требуют доделки:

Эти проекты **остаются в портфеле**, но запуск возможен только после закрытия соответствующих белых пятен (см. раздел 10).

## 7.7. Главный вывод по классификации

> **3 класса проектов = 3 параллельных потока работы**, которые могут идти независимо:
> 1. **Класс 3.1.1 (внешние API)** — стартуют **немедленно** после утверждения мандата. Не зависят от сервера и классификатора. 11 проектов.
> 2. **Класс 3.1.2 (локальный сервер)** — стартуют **после ввода сервера и утверждения классификатора**. 14 проектов.
> 3. **Класс 3.2 (автоматизация)** — внедряются **силами ДИТ** в рамках операционного бюджета. 11 проектов.
>
> Это позволяет **не ждать сервер** для запуска первых 11 пилотов и параллельно подготовить запуск следующих 14 после ввода инфраструктуры.

# 13. Приложения и глоссарий

## 13.1. Глоссарий

> Краткие пояснения для не-технических читателей.

**LLM (Large Language Model) — Большая языковая модель.** Нейросеть, обученная на текстах, умеет читать документы, отвечать на вопросы, генерировать тексты. Примеры: ChatGPT, Claude, GigaChat, YandexGPT, DeepSeek.

**RAG (Retrieval-Augmented Generation) — Генерация с дополнением из базы знаний.** Технология, которая не даёт LLM «галлюцинировать»: система ищет в корпоративной базе знаний релевантные документы и передаёт их LLM как контекст. Ответ строится **строго на основе предоставленных документов**.

**On-premise — Развёртывание на собственных серверах.** Программное обеспечение (включая LLM) работает внутри периметра компании. Данные не покидают компанию.

**MVP (Minimum Viable Product) — Минимально жизнеспособная конфигурация.** В контексте инфраструктуры: первый этап развёртывания на арендованных GPU-станциях, позволяющий запустить пилоты, не дожидаясь поставки серверов под заказ. Бюджет 0,8–1,2 млн ₽, срок 2–3 нед.

**CAPEX (Capital Expenditures) — Капитальные затраты.** Разовые крупные инвестиции (например, закупка серверной стойки). Противоположность OPEX (текущие операционные расходы, например подписки).

**ML (Machine Learning) — Машинное обучение.** Алгоритмы, которые обучаются на данных, а не программируются жёсткими правилами. В Холдинге: динамическое ценообразование, прогнозирование спроса, оптимизация рецептур.

**Predictive Maintenance — Предиктивная аналитика отказов.** ML-модель прогнозирует поломку оборудования до того, как она произошла, на основе данных датчиков (ток, вибрация, температура).

**Computer Vision (CV) — Компьютерное / техническое зрение.** Нейросети, которые анализируют изображения. В Холдинге: контроль качества упаковки, этикетки, обязательной маркировки.

**IIoT (Industrial Internet of Things) — Промышленный интернет вещей.** Датчики, контроллеры, шлюзы для сбора телеметрии оборудования. Без IIoT невозможна предиктивная аналитика.

**LIMS (Laboratory Information Management System) — Информационная система лаборатории.** Хранит протоколы испытаний, рецептуры, данные физико-химических показателей. В Холдинге — иностранный вендор, on-premise.

**SCADA — Система диспетчерского управления и сбора данных.** Снимает данные с датчиков на производстве (температура, давление, обороты).

**ERP (1C) — Система планирования ресурсов предприятия.** В Холдинге — внедряется параллельно. Решение зам. директора ИТ: до результатов внедрения ERP интеграции с ИИ — преждевременны.

**RPA (Robotic Process Automation) — Роботизация рутинных процессов.** Скрипты и боты, имитирующие действия пользователя в интерфейсах систем. Не требуют ИИ.

**ELMA** — система электронного документооборота, используется в Холдинге для согласования договоров, заявок на изменения, бизнес-процессов.

**ЗНИ — Заявка на изменения.** Формальный запрос от бизнеса в ДИТ на доработку информационной системы.

**ДИТ — Департамент информационных технологий.**

**ДПО — Договорно-правовой отдел.**

**ОДО — Отдел документационного обеспечения.**

**БК — Блок контроля.**

**ОРБП — отдел разработки бизнес-процессов / разработчики.**

**ФЭД — финансово-экономический департамент.**

**СУУ — система управленческого учёта.**

**ДЦ — направление динамического ценообразования.**

**ОТК — отдел технического контроля.**

**КЦ — колл-центр.**

**Анонимайзер** — внутренняя утилита, маскирующая персональные данные, ФИО, юрлица, бренды и коммерческую тайну перед отправкой в LLM (либо удерживающая их в локальной таблице соответствий). Используется для безопасной работы с внешними API.

**КТ — коммерческая тайна.**

**ПДн — персональные данные.**

**ETL (Extract, Transform, Load)** — извлечение, преобразование, загрузка: процесс перемещения данных из одних систем в другие.

**Stop/Go** — формальный критерий принятия решения по итогам пилота: масштабировать / доработать / закрыть.

**Product Owner** — представитель бизнеса, отвечающий за результат пилота (4–6 ч/мес обязательного участия).

**MAPE (Mean Absolute Percentage Error)** — средняя абсолютная процентная ошибка прогноза.

**OEE (Overall Equipment Effectiveness)** — общая эффективность оборудования.

**Time-to-Market** — время от идеи до отгрузки первому клиенту нового продукта.

**Datalake / Озеро данных** — централизованное хранилище. В контексте Холдинга — НЕ распределённый Hadoop за 50 млн ₽, а **консолидация в единой SQL-среде** с регламентированным доступом.

**[Вендор А]** — текущий вендор сервиса автоответов на отзывы *(название скрыто — NDA)*; обеспечивает 86% автоответов в техническом маркетинге, в эксплуатации 1.5 года.

**Медиалогия** — внешний сервис мониторинга упоминаний; обрабатывает [объём — NDA] упоминаний/мес для Холдинга.

**iSpring** — платформа корпоративного обучения; в Холдинге — 80+ модулей, ~70 программ обучения в год.

**E-staff** — система рекрутинга, интеграция с HH.ru.

**[Вендор Б]** — система прогнозирования спроса *(название скрыто — NDA)*; внедряется в департаменте планирования 2 года.

## 13.3. Список ключевых документов

### Внутренние документы Холдинга *(номера и названия скрыты — NDA)*

- СТО «Политика по управлению данными» (СМК);
- СТО «Использование искусственного интеллекта» (СМК);
- Политика управления данными (англоязычная версия).

### Аналитические документы аудита

- Аналитический обзор-гипотеза (~120 стр.) — гипотезы перед стартом аудита;
- Справка для руководства «Типы нейросетей» — ликбез по типам ИИ;
- Промежуточный отчёт по диагностике (≈ 65% обследования);
- Карта стейкхолдеров;
- Long-лист идей (исторический; отменён в пользу классификации по типу решения).

### Докладные записки для ГД

- Тезисная докладная записка по итогам аудита;
- Краткое резюме аудита для генерального директора.

### Протоколы и транскрибации

- 27 анонимизированных протоколов встреч;
- 10 анонимизированных транскрипций;
- 7 исходных транскрипций (подлежат анонимизации).

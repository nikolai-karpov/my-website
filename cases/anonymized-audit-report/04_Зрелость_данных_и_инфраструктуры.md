## 4.3. Узкие места инфраструктуры

### 4.3.1. Сервер на таможне (Блокер №1)

**Контекст:**

- Сервер согласован, оборудование в пути ~5 месяцев на таможенной проверке.
- GPU-видеокарты уже на месте.
- Серверная стойка ожидается **в течение 2 недель после сдачи отчёта**.
- Заявленная первичная нагрузка — **транскрибатор совещаний** (БК + общие).

**Последствия задержки:**

- Пилоты на коммерческой тайне отложены;
- Пилот по транскрибации (приоритет №1 у БК и финдира) — заморожен до прихода стойки;
- Риск создания **«серой зоны»** — сотрудники начинают использовать ИИ на телефонах и переносить результат руками (зафиксировано в диагностике).

### 4.3.2. Скорость работы ДИТ — структурный фактор

**Зафиксировано:**

- ДИТ оценивает 60% «тормозов» на стороне бизнеса (плохие ТЗ);
- Бизнес жалуется, что согласования ДИТ затягиваются «годами»;
- Совместное решение, согласованное на финальной встрече: **запустить пилот ИИ-аналитика для постановки задач** — снимет основной источник трения.

### 4.3.3. ERP (1С) — пока вне ИИ-периметра

**Зафиксировано на встрече с зам. директора ИТ:**

- Вендор 1С **не планирует** интегрировать ИИ;
- ERP внедряется параллельно;
- Решение: **дождаться результатов внедрения ERP**, потом возвращаться к интеграциям.

### 4.3.4. Закрытие API маркетплейсов

- API Wildberries закрыт с **сентября 2025** для данных конкурентов на полке;
- Маркетплейсы продают эту информацию как сервис;
- E-com получил 1 разработчика на весь проект отчётности по Ozon — узкое горлышко.

### 4.3.5. ИБ — текущая политика

**Согласовано на финальной сводной встрече с ДИТ + ИБ:**

✅ **РАЗРЕШЕНО** использовать внешние API:

- HR-кабинет (резюме, мониторинг зарплат, профили вакансий) — **данные не наши, КТ нет**;
- ИИ-тренажёр продаж — **на синтетических данных**;
- Корпоративная база знаний / RAG-навигатор по СТО — **после анонимизации, удаления имён, ФИО, юрлиц, брендов**;
- Дизайнеры — **уже работают с внешними сервисами по согласованию**.

❌ **ЗАПРЕЩЕНО** на внешних API:

- ИИ-аналитик для постановки ТЗ на ЗНИ (передаются данные с КТ);
- Анализ кода (платёжные реквизиты, бизнес-логика);
- Анализ записей разговоров продавцов (КТ — цены, объёмы, акции);
- Динамическое ценообразование (КТ — себестоимость);
- Финансовая аналитика и юридическая работа (есть прецеденты галлюцинаций).

### 4.3.6. Архитектура — приоритет №1 для ДИТ

**Зафиксировано в протоколе встречи с ДИТ:** без утверждённой архитектуры данных и классификатора данных невозможно полноценно внедрять ИИ-инструменты в коммерческие процессы.

## 4.4. Что есть в качестве зачатков ИИ

В компании уже есть точечные ИИ-кейсы — **это ценный фундамент**, не нулевая точка:

| Что | Где | Эффект |
|-----------------------------------------------|----------------------------------------------|-----------------------------------------------------------------------------|
| **[Вендор А] — сервис автоответов** | Технический маркетинг | 86% автоответов на отзывы, 1.5 года эксплуатации |
| **Telegram-бот подбора продукта** | Технический маркетинг | [объём — NDA] запросов/мес |
| **Медиалогия** | Блогеры/соцсети | [объём — NDA] упоминаний/мес обрабатывается |
| **Анонимайзер (прототип)** | HR | В разработке силами HR, основа для следующих пилотов |
| **CV-разметка для линии упаковки** | Производство (заводская команда) | В процессе |
| **Бот анализа интервью** | HR | Готов |
| **Claude Code, Gemini Pro** | Помощник операционного директора | Используется неофициально, как личный инструмент |
| **DeepSeek, GigaChat** | Тестируются внутренней командой | Сравниваются для внутренних задач |
| **Cursor (с DeepSeek/Opus)** | ДИТ | Тестируется для разработчиков |

**Вывод:** компания **не на нулевой точке**. Есть рабочие кейсы, есть команды, есть мотивация. Нет связующего звена, которое превратит точечные эксперименты в системную функцию.

## 4.5. Главный технический вывод

> Готовность данных в Холдинге — **на уровне «средней зрелости с разрозненными источниками»**. Это типичная ситуация для крупного производственного холдинга. Для пилотов Горизонта 1 (LLM-помощники, RAG, корпоративный советник) этого достаточно. Для пилотов Горизонта 2 (ML-прогнозы, предиктивная аналитика, оптимизация рецептур) — **нет**, требуется либо нормализация (1–6 мес.), либо инженерный проект (6–24 мес.).
>
> Главный инфраструктурный блокер — **сервер**. Без него часть пилотов нельзя начать даже теоретически. Решение этой проблемы (ввод сервера до конца месяца 1) — критический путь.

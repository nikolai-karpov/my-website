# Промпт: навигатор по репозиториям GitHub и SourceCraft на сайте-портфолио

Дата: 2026-09-27. Запускать в новой сессии Claude Code из `/Users/nik/projects/my-website`.

---

Ты — **оркестратор** задачи в проекте `my-website` (статический сайт-портфолио Николая Карпова,
`https://nikolai-pir-s-ru.sourcecraft.site/portfolio/`). Сам ты планируешь, принимаешь решения,
сверяешь результат и общаешься с Николаем. Вёрстку, сбор данных и проверки поручаешь
субагентам (инструмент Agent): одному агенту одну атомарную задачу. Модель агента выбирай
по сложности: `haiku` для механического сбора данных, `sonnet` для типовой вёрстки и проверок,
`opus` для ревью. Не уверен — бери на ступень выше.

## Цель

Страница-навигатор «где у меня какие проекты лежат» — консолидированная карта репозиториев
Николая на **GitHub** (`nikolai-karpov`) и **SourceCraft** — во **всех** его организациях
(`nikolai-pir-s-ru` — только одна из них, где лежит сам сайт). Требования:

1. На странице собраны данные из обеих площадок: проект, площадка, ссылка, краткое описание,
   язык или стек, дата последнего обновления. Если один проект лежит на обеих площадках
   (зеркало, как сам `my-website`: GitHub `origin` + SourceCraft `portfolio`), он показан
   **одной строкой** с двумя ссылками, а не двумя разными проектами.
2. Проекты сгруппированы по смыслу (свои проекты / сайты и портфолио / инструменты ИИ-агентов /
   форки чужих проектов для изучения и т.п.; итоговые группы предложи сам в плане).
   Форки чужих проектов визуально второстепенны: свои работы важнее.
3. Страница встроена в общую структуру портфолио: пункт в **меню** (шапке), чтобы её всегда
   можно было найти, и **ссылка в футере**.
4. Страница опубликована на боевом сайте и открывается по публичному адресу.

## Жёсткие ограничения

- **Сайт и репозиторий `my-website` на GitHub публичные.** Всё, что попадёт на страницу, увидят все.
  У Николая есть приватные репозитории (на GitHub сейчас: `hermes-agent`, `hermes-plugin-mempalace`,
  `claude-config`, `hermes-pipeline`, `pirs`; на SourceCraft узнаешь при сборе). **Ни названия,
  ни описания приватных репозиториев не публикуй без явного решения Николая по каждому.**
  По умолчанию приватные в публичную страницу не попадают совсем. Это первый вопрос в плане.
- **Доступ к SourceCraft — по SSH.** На хосте ключ `~/.ssh/id_ed25519` с **полными правами на все
  организации и репозитории** Николая; хост описан в `~/.ssh/config` (`Host ssh.sourcecraft.dev`,
  только IPv4). Рабочий формат адреса — `ssh://ssh.sourcecraft.dev/<организация>/<репо>.git`
  (проверено 27.09.2026 на `nikolai-pir-s-ru/portfolio`); форма `git@ssh.sourcecraft.dev:орг/репо.git`
  отвергается сервером («invalid params»). Раз ключ даёт полные права, при сборе данных — **только
  чтение** (`git ls-remote`, `git clone --bare`/`--filter=blob:none` во временный каталог); ничего не
  пушить, не создавать и не менять в SourceCraft, кроме штатной публикации самого сайта в Фазе 3.
- Секреты не печатать и не писать в файлы: ни приватный ключ, ни токен из
  `~/.config/sourcecraft/.env` (он используется HTTPS-remote `sourcecraft` этого репозитория и,
  возможно, API). GitHub — через `gh` (авторизован как `nikolai-karpov`).
- Данные на странице — **снимок, собранный скриптом**, а не набитые руками строки: скрипт сбора
  кладёт JSON в репозиторий, страница строится из него. Так навигатор можно обновить одной
  командой. Скрипт сам по себе никаких секретов в JSON не пишет.
- Не выдумывай. Если API SourceCraft для списка репозиториев найти не удалось, остановись
  и спроси, а не подставляй правдоподобные данные. Непроверенное помечай «НЕ ПРОВЕРЕНО».
- Ничего не удаляй и не переименовывай в существующих страницах, кроме правки меню и футера.
- Коммит и выгрузку делай только после того, как Николай одобрил готовую страницу.

## Порядок работы

### Фаза 0. Разведка (ты сам или один агент `sonnet`, только чтение)

Прочитай `AGENTS.md`, `docs/AGENTS.md`, `README.md`, `package.json`. Выясни и запиши в план:
- где лежат общие компоненты шапки и футера (они подгружаются через `fetch()`), как устроено меню;
- где живут страницы (`site-pages/`), стили (`assets/scss/`, `assets/css/main.css` — сборочный
  файл, руками не править), есть ли готовые шаблоны страниц, на которые стоит равняться
  (например, `webinars/navigator.html`, `site-pages/devledger.html`);
- **как сайт публикуется**: есть remote `sourcecraft` (сейчас HTTPS:
  `https://git.sourcecraft.dev/nikolai-pir-s-ru/portfolio.git`; тот же репозиторий доступен по SSH,
  см. ограничения) и workflow `.github/workflows/pages.yml`. Какой из путей даёт боевой адрес
  `…sourcecraft.site/portfolio/`, что запускает публикацию (push в какую ветку какого remote),
  как проверить, что выкатилось. Remote не перенастраивай без согласия Николая;
- **как получить полный список организаций и репозиториев SourceCraft.** SSH даёт доступ к git,
  но сам по себе список репозиториев не выдаёт. Найди способ перечисления: API SourceCraft
  (документация на sourcecraft.dev; аутентификация — токен из `~/.config/sourcecraft/.env`),
  SSH-команды сервера, если он их поддерживает, или иной штатный путь. Для каждого найденного
  репозитория проверь доступ по SSH (`git ls-remote ssh://ssh.sourcecraft.dev/<орг>/<репо>.git`)
  и узнай его видимость (публичный/приватный) — это нужно для правила о приватных. Если
  перечислить репозитории не удаётся, не собирай список по догадкам — спроси Николая.

### Фаза 1. План и вопросы Николаю (ты сам)

Составь короткий план: структура страницы, группы, поля, откуда какие данные, путь в меню и
футере, скрипт сбора, способ публикации, проверки, откат. Вместе с планом задай вопросы
**одним сообщением, не больше трёх, у каждого — рекомендуемый вариант**:
1. Какие приватные репозитории можно показать на публичной странице (рекомендация — никакие)?
2. Показывать ли форки чужих проектов (рекомендация — отдельной свёрнутой группой).
3. Название пункта меню (рекомендация — «Проекты» или «Репозитории»).

Дальше двигайся только после ответа.

### Фаза 2. Исполнение через агентов

1. **Сбор данных** (`haiku` или `sonnet`): скрипт в `scripts/` собирает публичные репозитории
   GitHub (`gh repo list nikolai-karpov --limit 200 --json …`) и SourceCraft, склеивает
   зеркала, применяет решение по приватным и форкам, пишет JSON в `site-pages/data/`.
   Проверь число записей вторым способом (например, прямым `gh api`).
2. **Вёрстка** (`sonnet`): страница в `site-pages/` в стиле сайта, адаптивная (телефон без
   горизонтальной прокрутки), с поиском или фильтром по группе и площадке, если записей больше
   ~20. Стили — через SCSS и `npm run build`, пре-коммит хук `npm run lint:css` не обходить.
3. **Меню и футер** (`sonnet`): пункт меню и ссылка в футере в общих компонентах, чтобы они
   появились на всех страницах сразу.
4. **Ревью** (`opus`): независимая проверка готовой страницы — нет ли на ней приватных
   репозиториев вопреки решению; все ссылки живые (HTTP 200); меню и футер работают на
   главной и минимум на двух других страницах; `.github/workflows/responsive-check.yml`
   или его локальный аналог проходит.

Агенты работают по очереди, если трогают одни файлы; сбор данных и вёрстку можно параллельно.

### Фаза 3. Показ, публикация, проверка

1. Покажи Николаю страницу локально (`npm run serve`, порт 8080), кратко: что на ней и откуда
   данные. Дождись одобрения.
2. Коммит (сообщение по-русски, по делу), выгрузка тем путём, который выяснен в Фазе 0.
3. Проверь боевой адрес: страница открывается, пункт меню и ссылка в футере на месте.
   Опубликованное без проверки на боевом адресе — не готово.
4. Итог Николаю: адрес страницы, как обновить данные (одна команда), что осталось открытым.

## Как писать Николаю

По-русски, без жаргона и англицизмов, коротко. Внутренние команды, JSON и пути в итоговых
сообщениях не показывай, если он не просил. Если от него ничего не требуется — так и пиши.

# Портфолио Николая Карпова

[![Deployed via GitHub Pages](https://img.shields.io/badge/GitHub%20Pages-deployed-blue?logo=github)](https://nikolai-karpov.github.io)

Простое, но продуманное портфолио, построенное на чистом HTML и CSS, с использованием современных подходов к структуре и поддержке контента. Основная цель — показать методологию работы и реальные кейсы с акцентом на ясность и удобство восприятия.

Представить:
- Философию и методологию работы
- Практические кейсы из профессионального опыта
- Аналитический подход к решению задач

## 🛠 Технологии

- **HTML5** — семантическая разметка
- **CSS3** — кастомные стили, адаптивная верстка

## 🛠️ Система сборки и зависимостей

### 📦 Архитектура зависимостей

Проект использует минимальный, но эффективный набор инструментов:

#### **Основные зависимости:**
- **Sass/SCSS** - препроцессор для модульных стилей
- **PurgeCSS** - оптимизация финального CSS (удаление неиспользуемых стилей)
- **Stylelint** - линтинг SCSS/CSS для поддержания качества кода

#### **Инструменты разработки:**
- **Husky + lint-staged** - автоматическая проверка кода при коммите
- **Concurrently + Live Server** - горячая перезагрузка в разработке
- **node-fetch** - для серверных тестов и проверок

### 🔧 Workflow сборки

#### **Процесс коммита (pre-commit hook):**
```
git commit → Husky → lint-staged → stylelint --fix → коммит
```

**Конфигурация:**
```json
{
  "precommit": "lint-staged",
  "lint-staged": {
    "*.scss": ["stylelint --fix"],
    "*.css": ["stylelint --fix"]
  }
}
```

#### **Процесс сборки:**
```
npm run build → 
  1. SASS компиляция (SCSS → CSS) → 
  2. PurgeCSS очистка → 
  3. Финальный оптимизированный CSS
```

**Скрипты:**
```json
{
  "sass:build": "sass assets/scss/main.scss:assets/css/main.css --style=compressed",
  "purge:css": "node purge.js",
  "build": "npm run sass:build && npm run purge:css"
}
```

### 🎯 Ключевые особенности системы

#### **1. Автоматический линтинг:**
- **Что:** Все SCSS/CSS файлы проверяются при каждом коммите
- **Как:** Husky + lint-staged + stylelint
- **Почему:** Гарантирует качество кода и соблюдение стандартов

#### **2. Оптимизация CSS:**
- **Что:** PurgeCSS удаляет неиспользуемые стили
- **Как:** Анализ HTML/JS файлов на предмет используемых классов
- **Почему:** Уменьшает размер CSS на 40-80%

#### **3. Модульная архитектура стилей:**
- **Что:** SCSS организован по методологии 7-1 Pattern
- **Как:** Разделение на base/, components/, layouts/, pages/, utils/
- **Почему:** Поддержка, масштабируемость, переиспользование

### 📁 Структура зависимостей

#### **devDependencies** (только для разработки):
- `husky`, `lint-staged` - автоматизация коммитов
- `stylelint`, `sass` - обработка стилей
- `concurrently`, `live-server` - дев-сервер

#### **dependencies** (продакшн):
- `node-fetch` - используется в тестовых скриптах
- (остальные зависимости - чистый HTML/CSS/JS)

### ⚠️ Важные особенности

#### **1. node-fetch используется только для:**
- Скрипта `test_fetch.js` (проверка доступности компонентов)
- Серверных тестов (не влияет на фронтенд)

#### **2. Нативный fetch() используется для:**
- `components-loader.js` - загрузка header/footer
- Браузерных операций (работает в современных браузерах)

#### **3. PurgeCSS настройки:**
- Сохраняет динамические классы (`active`, `hidden`, и т.д.)
- Сохраняет классы по паттернам (`btn-*`, `card-*`, `text-*`)
- Перезаписывает основной `assets/css/main.css`

### 🚀 Команды разработки

```bash
# Разработка с hot reload
npm run dev

# Сборка проекта
npm run build

# Проверка стилей
npm run lint:css

# Автоисправление стилей
npm run lint:css:fix

# Компиляция SASS
npm run sass:build

# Очистка CSS
npm run purge:css
```

### 🔍 Отладка проблем

#### **Если коммит не проходит:**
1. Запустите `npm run lint:css` для проверки ошибок
2. Исправьте ошибки или используйте `npm run lint:css:fix`
3. Убедитесь, что Husky активирован: `npm run prepare`

#### **Если сборка не работает:**
1. Проверьте пути в `purge.js` (должен сохранять в `assets/css/main.css`)
2. Убедитесь в наличии `assets/css/` папки
3. Проверьте SCSS синтаксис: `npm run sass:build`

## 🏗️ Архитектурные принципы

### 🧱 Архитектура BEM:
- Используется для компонентов: `.card--competency`, `.card__icon`, `.card__metric`
- Четкое разделение на блоки, элементы и модификаторы
- Упрощает поддержку и переиспользование

### 🎨 Цветовая палитра:
- `--primary-color: #4A90E2` (синий)
- `--gradient-primary: linear-gradient(135deg, #667eea 0%, #764ba2 100%)`
- `--dark-color: #2c3e50` (темный)
- `--light-bg-color: #f8f9fa` (светлый фон)
- `--neural-glow: rgba(74, 144, 226, 0.1)` (нейросвечение)

### 📏 Отступы:
- `--spacing-xs: 8px`
- `--spacing-sm: 16px`
- `--spacing-md: 24px`
- `--spacing-lg: 32px`
- `--spacing-xl: 48px`

### 🎭 Анимации и интерактивность:
- `@keyframes float` - плавание карточек

- `@keyframes pulse` - пульсация
- `@keyframes fadeIn` - плавное появление
- `data-aos` - анимации при скролле

### 📱 Адаптивные breakpoints:
- `max-width: 480px` - мобильные
- `max-width: 768px` - планшеты
- `max-width: 992px` - маленькие десктопы

### 📚 Типографика:

  - `--font-size-3xl: 2rem` (32px)

  - `--font-size-xl: 1.25rem` (20px)
- **H1**: `var(--font-size-4xl)`
- **H2**: `var(--font-size-3xl)`
- **H3**: `var(--font-size-2xl)`

## 🔧 Как работает подгрузка header/footer?

```javascript
// Загрузка шапки
fetch('components/header.html')
  .then(response => response.text())
  .then(data => {
    document.getElementById('header').innerHTML = data;
  });

// Загрузка подвала
fetch('components/footer.html')
  .then(response => response.text())
  .then(data => {
    document.getElementById('footer').innerHTML = data;
  });
```


> Это позволяет легко поддерживать единый дизайн по всему сайту без использования серверных технологий.

# Подводные камни Direct API

Поведенческие особенности, на которых пользователь чаще всего «спотыкается» при работе с агентом. Упоминать **только когда релевантно** — не выдавать списком превентивно.

## ID кампании меняется при переносе между аккаунтами

При переносе кампании из одного логина в другой Яндекс выдаёт **новый ID**, и история показов/кликов **не переносится** — статистика начинается с нуля.

**Симптом:** пользователь говорит «куда делась моя статистика, мы же только перенесли?» — спроси, не происходил ли перенос между аккаунтами в последний месяц. Если да — объясни, что это известное поведение Яндекса, а не баг агента.

## Готовый отчёт хранится 5 часов на стороне Яндекса

Reports API после успешной генерации удерживает готовый файл ровно 5 часов. Это влияет только на повторные запросы с теми же параметрами — наш клиент всё равно перезапросит, просто на стороне сервера это будет новая работа.

## Wordstat — отдельный Search API

Wordstat в Hermes подключён отдельными инструментами `yandex_wordstat_*` через Yandex Search API v2 / AI Studio. Для спроса, частотности, сезонности и регионов используй навык `yandex-wordstat`, а не Direct OAuth.

Настройка Wordstat: `YANDEX_API_KEY` + `YANDEX_FOLDER_ID`. `YANDEX_DIRECT_TOKEN` и `YANDEX_DIRECT_LOGIN` нужны для Direct, но не для Wordstat.

## OAuth-токен живёт ~1 год

Token Yandex OAuth по умолчанию имеет срок ~365 дней (некоторые типоразмеры — 90 дней). При истечении API вернёт `HTTP 401` или `Invalid authentication token`.

**Чиним так:** перевыпустить токен через `https://oauth.yandex.ru/authorize?response_type=token&client_id=<CID>` тем же логином, заменить значение `YANDEX_DIRECT_TOKEN` в `.env` репозитория. Client ID/Secret сохранять — они не меняются.

## error_code 58 «Незавершенная регистрация»

Возвращается, пока заявка на доступ к API не одобрена в кабинете Директа. **Это не баг приложения** — это процесс модерации Яндекса.

**Чиним так:** `direct.yandex.ru` → Настройки → API → Мои заявки → Новая заявка. Полный или Тестовый доступ. Срок рассмотрения — до 7 рабочих дней. Sandbox тоже требует одобрения.

## error_code 152/9000 «Недостаточно баллов»

Закончились Units. Лимит ~64 000/сутки, обновление каждый час. Наш toolset потребляет до ~2 000/сутки на пиковой нагрузке, поэтому пустой остаток обычно означает, что другое приложение (внешний скрипт) тоже работает на этом аккаунте.

**Чиним так:** подождать до следующего часа. Если повторяется регулярно — пересмотреть параллельные интеграции.

## HTTP 502 в Reports

Не отказ — это «отчёт превысил время генерации». Наш клиент автоматически ретраит как 201/202. Если ловится после 180 секунд — отчёт слишком большой, попроси пользователя сузить период или campaign_ids.

## Сезонность портит «аномалии»

Если сравнение «эта неделя vs прошлая» совпало с праздниками или сезонным спадом (типа майских или август-сентябрь в B2B) — `yandex_direct_anomalies` подсветит «провал», которого на самом деле нет. Пользователь обычно сам это понимает, но при подаче упоминай: «учти, что на прошлой неделе были праздники».

## Конверсии в Direct ≠ конверсии в Метрике

Direct может показывать `Conversions` из своих внутренних целей, но **достоверный источник конверсий** — Yandex Metrika (`yandex_metrika_conversions`). При расхождении доверяй Метрике.

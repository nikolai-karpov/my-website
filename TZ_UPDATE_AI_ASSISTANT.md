# Техническое задание (ТЗ)
## Обновление кейса «Персональный ИИ-ассистент руководителя» в портфолио

---

### 1. Основание

На проекте `hermes-agent` за последние 2 недели (май 2026) реализовано три крупных подсистемы, которые не отражены в текущей странице кейса `site-pages/ai-assistant.html` (622 строки):

1. **Model Orchestrator** — интеллектуальный routing моделей
2. **Model Arena** — observability и телеметрия
3. **Background Review** — самообучение агента

Эти подсистемы подчёркивают **архитектурный уровень** решения (не один чат-бот, а мультиагентная система) и должны быть отражены в портфолио.

---

### 2. Цель

Синхронизировать описание кейса с реализованными фичами, чтобы портфолио демонстрировало:

- **Мультиагентную оркестрацию** — routing задач между моделями разной мощности, escalation, quota management
- **Enterprise-observability** — телеметрия каждого вызова, вердикты, ежедневные дайджесты
- **Самообучающуюся систему** — агент рефлексирует после каждого тура и улучшает навыки/память без участия человека

### 4. Задачи по обновлению

#### Задача 1. Новая секция «Интеллектуальный routing моделей»

**Место:** После секции «Архитектура — что под капотом» (строка ~138)

**Содержание:**
- 3-tier routing: LIGHT (glm-4.5-air) → MEDIUM (glm-4.6/4.7) → HEAVY (glm-5.1)
- Эвристический классификатор без ML (по размеру контекста, tool calls, ключевым словам)
- 5-step ordered escalation chain при качественных ошибках
- Экономия ~47% квоты при 30% heavy-туров
- Quota tracking с двухпороговым cap (warn 20% / hard 8%)
- 120 тестов, golden set на 30 сценариев

**Тон:** Подчёркивает архитектурный уровень — «система с собственным планировщиком ресурсов», а не «один чат-бот».

---

#### Задача 2. Новая секция «Наблюдаемость агентной системы»

**Место:** После секции «Интеллектуальный routing моделей»

**Содержание:**
- Телеметрия каждого API-вызова в SQLite (модель, tier, исход, latency, токены)
- CLI-команды: `hermes arena stats`, `hermes arena digest`
- Парсинг вердиктов (/done, /pause, /fail) в gateway
- State schema v12 — `model_arena_attempts` + `session_verdicts`
- Ежедневный cron-отчёт с агрегацией за 24ч

**Тон:** Enterprise-уровень — «metrics/dashboards для ИИ-ассистента».

---

#### Задача 3. Новая секция «Самообучение и рефлексия»

**Место:** После секции «Наблюдаемость агентной системы»

**Содержание:**
- После каждого тура — daemon thread fork агента
- Ревьюит диалог: стоит ли обновить память/навыки
- Tool whitelist (только memory + skill tools), основной диалог не трогает
- Пишет `bgreview_decision` + `bgreview_usage` в `orchestrator.jsonl`
- Fixed light model strategy — не уводит на платные модели

**Тон:** «Агент улучшается сам, без ручного дообучения».

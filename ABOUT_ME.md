## 1. Кто я в одном абзаце

Архитектор и интегратор корпоративных ИИ-систем. Совмещаю три роли в одном лице: бизнес-аналитик (структурированные интервью, BPMN, ROI-портфели), архитектор и интегратор ПО (многослойные веб-платформы с доведением до промышленного внедрения), архитектор мультиагентных ИИ-систем (RAG, цепочки агентов, on-prem LLM-контур, guardrails). Профильная специализация — внедрение нейросетей в корпоративный контур крупных промышленных и проектных организаций с обязательным согласованием со службой ИБ. Публичное позиционирование на сайте: «Архитектор ИИ-систем для промышленности».
Стаж работы и предыдущие должности в портфолио не указаны — **нет данных** (выводится только по объёму и зрелости артефактов; на встрече называть стаж не следует без сверки с резюме).

## 2. Экспертиза по внедрению ИИ (приоритетный раздел)

### 2.1. Реальные внедрения и пилоты в организациях

- **ПИР-Система (pir-s.ru) — в промышленном внедрении.** Многослойная веб-платформа для управления проектно-изыскательскими работами. Спроектирована с нуля и доведена до промпрома. ИИ-сценарии: расширенная классификация типов исходно-разрешительной документации (ИРД), валидация XML, модульный анализ с фрагментацией под лимиты LLM, поиск коллизий между документами и разделами, машинно-проверяемые чек-листы нормконтроля, генерация ТЗ на разделы проектной документации. Демо: `pir-s.ru`, страница про ИИ — `pir-s.ru/ai`. **Роль: архитектор и идеолог, проектирование с нуля до промвнедрения.**

- **Аудит готовности крупного промышленного холдинга к ИИ (заказчик анонимизирован) — завершён, защита проведена.** Единый комплекс из трёх частей: (1) аудит — 27 структурированных интервью, паспорт данных по 16 функциональным направлениям, портфель десятков ROI-гипотез, отчёт из 13 разделов; (2) собственная SPA «Матрица проектов» (Vite + React TS, Node) для управления портфелем с квадрантами P/I и Short/Long-листами; (3) просветительский трек — 34 разобранных мировых ИИ-кейса по единому шаблону как бенчмарк-база, отдельные обзоры под каждое подразделение перед интервью. Срок — **7 рабочих недель** (сокращён заказчиком с 12). Защита перед топ-менеджментом, ИТ и службой ИБ. **Роль: единоличный исполнитель.**

- **Pseudonymizer MVP — в эксплуатации.** Контейнеризованный сервис обезличивания документов: гибридная детекция (regex + spaCy NER + словарь кастомных типов), детерминистичные плейсхолдеры на стабильном хэше, сессии обратимого восстановления, асинхронная очередь с polling, отдельный JSON API для интеграций (в т. ч. email-воркеры), rate limiting через slowapi, метрики Prometheus. Форматы: txt, docx, pdf, md, xlsx. Стек: Python 3.11, FastAPI, spaCy (ru/en), SQLite, Docker Compose. Артефакты — HLD защищённого LLM-контура (Zero Trust, DLP-шлюз, SIEM, ротация ключей, локализация логов в РФ) и матрица guardrails по доменам — применялись в реальных согласованиях с корпоративной ИБ. **Роль: архитектор и разработчик.**

- **Персональный ИИ-ассистент руководителя — рабочая сборка для демо.** Мультиагентная on-prem система «встреча → протокол → согласование → календарь → контроль». Архитектурные элементы: Hermes Agent (фреймворк Nous Research, MIT), локальный речевой конвейер (GigaAM + Pyannote 3.1 + Resemblyzer), 3-tier model routing (glm-4.5-air / glm-4.6-4.7 / glm-5.1) с ordered escalation chain из 5 шагов и двухпороговым quota-tracker (warn 20% / hard 8%), телеметрия Model Arena в SQLite (`model_arena_attempts`, `session_verdicts`, schema v12, CLI `hermes arena stats/digest`, ежедневный cron-отчёт), Background Review (daemon thread fork, fixed light-model), память — ChromaDB + ONNX-эмбеддинги + граф знаний MemPalace, Celery+Redis для пайплайна, адаптеры Exchange/Google Workspace, VK Teams, Telegram, журналирование в SIEM (ELK, Splunk). Покрытие — **120 unit-тестов, golden set из 30 сценариев**, заявленная экономия квоты **~47%** на типичном распределении трафика. План пилота: 4–7 недель.

- **Self-hosted n8n production-пайплайн (обработка интервью) — в проде.** **143 ноды, 181 соединение, 28 ветвлений (20 If + 8 Switch), 31 узел error-handling, 6 функциональных кластеров.** Один Telegram-бот как точка входа, трёхстадийная транскрипция AssemblyAI, multi-LLM (OpenAI ↔ DeepSeek с fallback), 6 предметных веток анализа + Complex/Corporate, каталог промптов с UI в Telegram, state-machine диалога без внешнего хранилища, self-diagnosis. **Не туториал и не сборка из шаблонов** — собственная архитектура. **Роль: архитектор и разработчик воркфлоу.**

- **Платформа управления перевозчиками (промышленный холдинг) — дизайн и прототип сданы, пилот на паузе по решению заказчика.** 5 контуров (YMS с коэффициентами К1–К4, групповая обработка заказов, агрегатор тарифов ТК, тендеры/смарт-контракты/штрафной модуль с **ИИ-генерацией претензий**, **ML-сигналы перезатарки на горизонт 7–14 дней с порогами 90%/95%**, авторейтинг подрядчиков). Интеграции: 1С УПП через HTTP-сервисы (готовность к 1С:ERP), WMS, BI, ELMA, ДИАДОК, публичные API ТК. HTML-прототип Yard Management — рабочий. Учёт ИБ с этапа дизайна: ролевая модель, оптимистическая блокировка, аудит-трейл, «Маршруты данных» для службы ИБ.

- **Промпт-инжиниринг и менторство для научно-исследовательской группы.** Проектирование рабочих промптов под научно-технические публикации в отраслевых журналах: «анатомия промпта» из 8 блоков (ролевая модель, ИМРАД, СИ-единицы, объём 9 000–18 000 знаков, маркеры [ссылка нужна:…] против фабрикации источников). Заявленный результат: время на черновик «сокращается в разы», доработка 10–20%, после 2–3 совместных статей команда работает самостоятельно. **Роль: промпт-инженер, методолог, ментор.**

- **Генератор стратегий B2B-продаж (`prompt_generator.html`).** Self-hosted web-приложение для генерации персонализированных промптов на основе данных компании из Google Sheets. Включает «нулевой шаг» проверки гос. статуса (44-ФЗ/223-ФЗ), карту ЛПР, источники Spark/Контур.Фокус/LinkedIn/TenChat/госзакупки, антифабрикационные ограничения.

## 3. Опыт работы с организациями / корпоративным сегментом

- **Крупный промышленный холдинг (анонимизирован).** 7-недельный аудит, 27 интервью, 16 функциональных доменов: собственное производство, R&D, коммерческий блок, продажи через маркетплейсы, распределённая сеть складов. Финальная защита перед топ-менеджментом, ИТ-директором, службой ИБ. Подготовка отдельных тематических обзоров под каждое направление перед интервью. Параллельный продукт — SPA «Матрица проектов» как рабочий инструмент управления портфелем после аудита.
- **Та же организация (или связанная — требует проверки) — логистика.** Платформа управления перевозчиками для промышленного холдинга: дизайн, прототип, интеграции с корпоративным ландшафтом (1С УПП → 1С:ERP, WMS, BI, ELMA, ДИАДОК), согласование маршрутов данных со службой ИБ.
- **Проектная организация (или связанные — требует проверки) — ПИР-Система.** Промышленное внедрение SaaS-платформы под проектно-изыскательские работы; пользователи — инженер-проектировщик и ГИП.
- **Научно-исследовательский коллектив.** Менторство и промпт-инжиниринг для регулярной интеллектуальной работы (научно-технические публикации).

### Что показывает работу со взрослым корпоративным заказчиком

- Учёт ИБ как **входного условия**, а не «вишенки на торте»: HLD защищённого LLM-контура защищается до пилота; матрица guardrails по доменам; собственный псевдонимизирующий шлюз как фундамент.
- Интеграции через **API/REST/GraphQL без файлового обмена и без прямых SQL к чужим базам** (декларация архитектурного подхода на ПИР-Системе).
- **API-first wrapper** над 1С (HTTP-сервисы с готовностью к 1С:ERP) — миграционная готовность с этапа дизайна.
- Документирование «грабель» и runbook как часть продукта; журналы в формате «симптом → корневая причина → как лечить».
- Защита решений перед топ-менеджментом, ИТ и службой ИБ как часть рабочего процесса.
- Управленческая зрелость заказчика учтена явно: срок аудита сокращён с 12 до 7 недель — выдержан.

## 4. Ключевые проекты (кейсы)

> Сортировка — по релевантности к «внедрение ИИ в крупной организации».

### Кейс 1. Аудит готовности крупного промышленного холдинга к ИИ

- **Задача:** оценить готовность холдинга к ИИ, сформировать портфель приоритезированных инициатив, защитить перед топ-менеджментом, ИТ и ИБ.
- **Что сделал:** структурированные интервью (27 штук, аудиозапись по согласию, транскрипция, анонимизация, индивидуальные протоколы); паспорт данных по 16 направлениям; классификация гипотез в три класса (внешние API через шлюз псевдонимизации / on-prem LLM / автоматизация без ИИ); приоритезация через бинарные «важно × реализуемо» в квадрантах Q1–Q4; собственная SPA «Матрица проектов» как рабочий инструмент после сдачи; отдельные тематические обзоры под каждое подразделение перед интервью; отчёт из 13 разделов; защита перед топ-менеджментом, ИТ-директором и службой ИБ.
- **Стек/подход:** структурированные интервью, BPMN AS-IS, портфельная матрица P/I, Vite+React TS для SPA, Node-скрипты для импорта/экспорта, экспорт Short/Long-листов в Markdown.
- **Результат:** аудит сдан в **7 рабочих недель вместо 12** запланированных; 34-кейсовая бенчмарк-база разобранных мировых ИИ-внедрений (McCormick × IBM, Bridgestone × Enthought, NotCo Giuseppe, BMW × NVIDIA AIQX, ArcelorMittal, TSMC, Schaeffler × Siemens Industrial Copilot, Unilever, BlueScope × Senseye, Federal Package × Cognex, Hyundai, Nestlé, Atria × RELEX, Perfetti Van Melle, JPMorgan, Microsoft, Siemens, Газпром нефть «Алхимик», FUCHS × Intellegens и др.) как актив для будущих проектов; финансово-экономический обзор 50+ страниц; пять материалов под коммерческий блок; pptx+html-артефакт под производство.

### Кейс 2. ПИР-Система — платформа управления ПИР с ИИ-помощником ГИПа

- **Задача:** управление проектно-изыскательскими работами + ИИ-помощник для главного инженера проекта по работе с исходно-разрешительной документацией.
- **Что сделал:** спроектировал с нуля и сопровождал до промышленного внедрения; пять архитектурных слоёв в одном репо (client / server BFF / hasura / deploy / seeder+docs); идемпотентные SQL-миграции Hasura; разделение «домен через GraphQL, ИИ-сценарии через REST»; demo-ветка с mock-эндпоинтами для развития UX без блокировки на ML; runbook демо-сервера; журналы «грабель» как часть продукта.
- **Стек:** React (CRA + craco), Node/TypeScript BFF, Hasura/GraphQL, Postgres, Docker, nginx; зарезервированы слоты под Python-runtime анализа, MCP-server, Qdrant.
- **ИИ-сценарии:** классификация типов документов ИРД, валидация XML, фрагментация под лимиты LLM, поиск коллизий, машинно-проверяемые правила нормконтроля, генерация ТЗ на разделы.
- **Результат:** **в промышленной эксплуатации**, демо доступно по `pir-s.ru`, отдельная страница `pir-s.ru/ai`.

### Кейс 3. Pseudonymizer MVP — фундамент работы с внешними LLM

- **Задача:** дать организации возможность безопасно использовать публичные LLM без утечки ПД и коммерческой тайны.
- **Что сделал:** спроектировал и реализовал контейнеризованный сервис обезличивания (sync + async API, email-воркеры), сессионная модель обратимого восстановления, гибридная детекция, отдельный TLS-сценарий compose для локальной приёмки; HLD защищённого LLM-контура по Zero Trust; матрица guardrails по доменам; политика защиты коммерческой тайны с приложениями для согласования с ИБ.
- **Стек:** Python 3.11, FastAPI, spaCy (ru/en), SQLite, Docker Compose, slowapi, Swagger, Prometheus.
- **Результат:** **MVP в эксплуатации**, интеграционный API доступен; артефакты прошли реальные согласования с корпоративной ИБ и стали методологической базой для пилотов в холдинге.

### Кейс 4. Персональный ИИ-ассистент руководителя

- **Задача:** замкнуть цикл «встреча → протокол → согласование → календарь → контроль исполнения» без выхода чувствительных данных из периметра.
- **Что сделал:** мультиагентная архитектура с локальным речевым конвейером, 3-tier маршрутизацией моделей, телеметрией каждого вызова, ежедневным digest, рефлексией после каждого тура, локальной векторной памятью и графом знаний, шлюзом приватности перед облачной моделью.
- **Стек:** Hermes Agent, Qwen3 + Llama-3.3 (on-prem), GLM-каскад через шлюз, GigaAM + Pyannote 3.1 + Resemblyzer, ChromaDB + ONNX-эмбеддинги, MemPalace, Celery+Redis, FastAPI+spaCy для псевдонимайзера, Exchange/Google/VK Teams/Telegram-адаптеры, ELK/Splunk-журналирование.
- **Результат:** **рабочая сборка для демо**, 120 unit-тестов, golden set 30 сценариев, расчётная экономия квоты ~47% против запуска всего на heavy. Цикл внедрения у клиента — 4–7 недель.

### Кейс 5. Self-hosted n8n production-пайплайн на 143 нодах

- **Задача:** автоматизация обработки аудиозаписей собеседований и оценочных бесед.
- **Что сделал:** воркфлоу из 143 нод с локальной обработкой ошибок, retry с backoff, разделением retryable/критических ошибок, state-machine диалога без внешнего хранилища, multi-LLM fallback OpenAI↔DeepSeek, self-diagnosis-отчёты в чат админа.
- **Стек:** n8n self-hosted, Telegram Bot API, AssemblyAI, OpenAI, DeepSeek, SMTP.
- **Результат:** **в проде, развивается**; артефакт навыка production-автоматизации.

### Кейс 6. Платформа управления перевозчиками (промышленный холдинг)

- **Задача:** сквозная веб-платформа для логистики промышленного холдинга — управление дворами, тендерами, тарифами, перезатаркой.
- **Что сделал:** дизайн-документ «Описание решения. Версия 2.0»; HTML-прототип Yard Management; интеграционная карта с 1С УПП через HTTP-сервисы (готовность к 1С:ERP), WMS, BI, ELMA, ДИАДОК, публичными API ТК; «Маршруты данных» для службы ИБ; правильное разграничение «ML как сигнал, не как автодействие».
- **Стек:** 1С УПП → 1С:ERP, WMS, BI, ELMA, ДИАДОК, ML/ИИ, HTML-прототип.
- **Результат:** дизайн и прототип сданы, **пилот поставлен на паузу решением заказчика** (не закрыт по технологии).

### Кейс 7. Промпт-инжиниринг и менторство для R&D-коллектива

- **Задача:** сделать научно-исследовательскую группу самостоятельной в работе с LLM при написании статей.
- **Что сделал:** «анатомия промпта» из 8 блоков под публикации в отраслевых журналах (ИМРАД, СИ-единицы, маркеры против фабрикации источников), сессии менторства, итеративная доработка.
- **Результат:** заявлено — после 2–3 совместных статей команда работает самостоятельно, доработка 10–20% черновика.

## 8. Слабые места / пробелы (для внутренней подготовки, не для показа)

> Что технически грамотный собеседник может «прижать» при первом разговоре. Это не критика портфолио, а карта рисков, которую полезно держать в голове.

1. **Стаж и предыдущие места работы не указаны.** На сайте нет ни биографии, ни трудовой истории. Главный инженер проекта в крупной компании привык видеть в собеседнике опыт работы в проектных институтах / отраслевых организациях. Подготовить устный нарратив: где и сколько работал, в каких отраслях, какие именно проекты сданы в продакшен.

2. **Заказчики анонимны.** Холдинг, перевозчики, ассистент руководителя — заказчики не названы. Это нормально по NDA, но снижает «социальное доказательство». На встрече важно уметь произнести (где этично): отрасль, размер компании, кто принимал работу, как организацию воспринимает рынок.

3. **Нет количественного результата у заказчика.** В кейсе ассистента руководителя прямо сказано «точные показатели возможны только после пилота — до измерений называть проценты было бы нечестно». В аудите холдинга — порядки эффекта, не фактические цифры. ROI-портфели гипотетические, не «вот мы сэкономили X млн ₽ в год». ГИП может спросить: «А что в итоге дало деньги заказчику?» — ответ должен быть готов, пусть в порядках.

4. **Команда не показана.** Везде роль формулируется в единственном числе (архитектор, разработчик, идеолог, исполнитель). Это может быть как реальный фактаж (фриланс/индивидуальная экспертиза), так и недоформулированность. Главный инженер проекта работает в командах по 50+ человек — у него возникнет вопрос «вы один это всё делали?». Стоит уметь честно объяснить модель работы.

5. **Нет публичных регалий.** В портфолио не упомянуты конференции, статьи в отраслевых журналах, сертификации (AWS/GCP/Yandex, безопасность, методологии). Если такие есть — обязательно упомянуть на встрече. Если нет — приготовиться к тому, что собеседник может спросить «а кто вас в отрасли знает?».

6. **«ИИ для промышленности» — но в портфолио мало OT/SCADA/ICS-конкретики.** Главный позиционирующий слоган — «ИИ в промышленность системно». Но из реальных собственных кейсов в промышленный контур заходят ПИР-Система (это **проектирование**, а не **производство**) и аудит холдинга (преимущественно бэк-офис, коммерция, склад). Глубоких собственных кейсов на цеху, по PdM/CV-QC, у Карпова **нет** — есть только разбор чужих мировых кейсов (Bridgestone, BMW, ArcelorMittal, TSMC и т. д.). Это нормально для аналитика, но проектный ГИП может задать «а у вас лично что-то стояло на производственной линии?» — ответ должен быть честный.

7. **Часть стека упомянута, но глубина непроверяема.** Qdrant, Deepgram, Yandex Cloud Functions, Make — упомянуты в стеке, но в кейсах глубоко не раскрыты. **Требует проверки** перед встречей: что готов разобрать на уровне «реально применял», что — «пробовал/читал».

8. **Нет ни одного собственного кейса в нише собеседника — крупной проектной компании.** ПИР-Система — это **продукт для** проектной отрасли, но не «я внедрил ИИ в проектном институте N». Стоит заранее проговорить мостик: «вот что я уже умею для процессов проектирования» → «вот что это может дать в вашей компании».

9. **ИИ-ассистент руководителя — пока демо.** Заявлен как «рабочая сборка для демонстрации», пилотов у клиента ещё не было. Если собеседник спросит «у кого это уже работает?» — честный ответ: пока внутренняя сборка, готова к пилоту.

10. **Платформа перевозчиков — пилот на паузе.** Это нормальная реальность, но формулировать стоит чётко: «не закрыт по технологии, а решением заказчика», без оправдательного тона.

11. **Биография «человеческая».** Поскольку с этим конкретным собеседником вы знакомы лично, **он знает вас не как специалиста**. Здесь риск двойной: с одной стороны, надо «переключить» восприятие на профессиональное; с другой — не пережать (он не любит, когда люди вдруг становятся «другими»). Стоит начать с конкретного кейса, который ближе всего к его миру (ПИР-Система), а не с самопрезентации.
